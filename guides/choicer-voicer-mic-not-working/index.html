Choicer Voicer microphone not working

Fix browser permission, Windows or macOS privacy, the wrong input, Bluetooth switching, iframe focus, and competing audio apps.

Last verified: August 27, 2026
Test my microphoneRead the steps ↓
01

Run the quickest microphone test

Open the site's microphone test before changing several settings at once. If its meter responds, the browser can access the device and the remaining problem is more likely iframe focus, game state, or a game-specific selection. If the test is silent, continue with browser and operating-system checks.

02

Allow the microphone in Chrome or Edge

Select the permission icon beside the address bar and set Microphone to Allow for choicervoicer.site. Confirm the selected input is the device you are actually speaking into. After changing permission, reload the page and press Start Game again so the cross-domain iframe can request a fresh stream.

03

Check Windows 11 privacy and input

Open Settings, then Privacy & security, Microphone. Enable microphone access and allow desktop apps to use it. In System, Sound, Input, choose the intended device and confirm its level meter moves. A webcam, monitor, controller, or disconnected headset can remain selected even when another microphone is physically connected.

04

Check macOS privacy and input

Open System Settings, Privacy & Security, Microphone and allow the browser. Then open Sound, Input and select the correct device. Quit and reopen the browser if macOS granted access while it was already running. Managed work or school devices may enforce a policy that the website cannot override.

05

Remove app and Bluetooth conflicts

Close Discord, OBS, Zoom, Teams, voice chat, screen recorders, and other tools that may hold exclusive access or change the default input. Bluetooth headsets can switch between high-quality playback and call mode when the microphone activates; test a wired headset or built-in microphone to identify whether that mode switch is the cause.

06

Check iframe focus, HTTPS, and mobile limits

The game runs in a cross-domain iframe. Click inside it before starting a round, and use the new-tab fallback if a privacy extension blocks embedded permission. The live website uses HTTPS, which microphone access requires. Mobile browser audio, tab switching, and permission behavior vary, so a current desktop Chrome or Edge session remains the recommended diagnostic baseline.

07

If sound records but playback is empty

Lower speaker volume or use headphones to prevent echo cancellation from suppressing the take. Confirm the input level is neither muted nor clipping. Retry at a comfortable speaking distance, then reload only after preserving anything you need from the current round.

08

Use one-change troubleshooting

Change one layer at a time and repeat the same ten-second test. Begin with the site microphone meter, then browser permission, operating-system privacy, selected input, competing apps, and finally the embedded game. If several settings change together, a temporary success will not reveal which fix mattered. Record the working device name and browser so the next session can begin with the same baseline. Do not repeatedly clear all browser data because that can remove locally stored Packs and other useful session state.

09

Know when the problem belongs to the game host

If the site microphone test moves but the embedded game remains silent, the parent website has already proved that the browser can capture input. Click inside the game, restart its round, and use the open-in-new-tab fallback. Disable only the extension most likely to block embedded media and retry. A game-host outage, cross-origin permission rule, or game-specific device bug cannot be repaired by changing the parent page. Preserve the exact browser, device, error text, and reproduction steps before reporting the issue.
