How to create a Choicer Voicer Dub Pack

Plan permitted media, lines, timestamps, characters, captions, and validation.

Last verified: August 27, 2026
Open Pack LibraryRead the steps ↓
01

Start with rights

Create or license the source material and document what downstream users may do with it. Distribution permission is different from permission to view a video online.

02

Build clear metadata

Give every line a start, end, speaker, caption, and stable identifier. Keep assets in predictable folders and avoid absolute paths tied to one computer.

03

Validate before sharing

Check ordering, duration, missing files, loudness changes, caption accuracy, and a clean import on another device. Include creator and license notes with the package.

04

Choose a focused source

Start with media you created or are permitted to transform. A short scene with clear speech and a manageable number of characters is easier to test than a full episode. Record the source, creator, license or permission, and any attribution that must travel with the Pack.

05

Turn moments into usable clips

Choose the spoken moments that should become prompts. Trim silence without cutting the beginning or ending of a line, keep loudness reasonably consistent, and use stable descriptive file names. WAV, MP3, and OGG are the safest browser-oriented audio choices in the current workflow.

06

Organize the Pack

Keep audio in predictable folders and avoid absolute Windows paths, duplicate names, hidden system files, or executable content. Add a clear Pack title, creator credit, source note, version, and a short description of the scene. If character or caption information is known, keep it factual rather than inventing dialogue that is not present in the source.

07

Test a clean import

Create the Pack locally, import it into a fresh browser session, and play several prompts in their intended order. Check missing files, clipping, long silence, unexpected volume jumps, and whether credits remain visible. Ask another person to repeat the import before publishing the archive.

08

Write timing data another player can understand

For every playable moment, record a stable clip identifier, speaker, start time, end time, and caption only when the words have been checked and may be displayed. Use seconds or one documented timestamp format consistently. Start and end values must increase, stay within the source duration, and leave enough space for the complete word. If dialogue cannot be published, a speaker-and-time guide is still useful, but it must clearly say that it is not a transcript.

09

Publish a maintainable Pack version

Give the archive a version, creation date, source credit, contact route, and short change log. Test it in a clean browser profile rather than relying only on the device that created it. Ask one other person to import, select, play, remove, and restore the Pack. Keep the original project and permission record outside the ZIP. When a source or file changes, publish a new reviewed version instead of silently replacing an archive whose size and contents no longer match the directory page.
